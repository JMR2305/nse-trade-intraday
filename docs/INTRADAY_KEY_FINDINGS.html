NSE Trader — Intraday Architecture: Key Findings

Read-only analysis  ·  July 18, 2026  ·  No code was modified

1. Current Architecture Snapshot

The existing platform is a pnpm monorepo built for swing trading (multi-day holds on NSE equities). It consists of:

  • React/Vite Web Dashboard — 43 pages, TanStack Query, Recharts, Tailwind/Radix UI
  • Expo Mobile App — 6 tab screens, mirrors core dashboard data
  • Node.js/Express API Server — TypeScript, Pino logging, PostgreSQL via Drizzle ORM
  • Python Trading Engine — Spawned as a child process per API request (main.py CLI dispatcher)
  • Market Data — yfinance (daily OHLCV, primary) + Zerodha Kite REST quotes (30 s TTL)
  • Persistence — PostgreSQL + JSON flat-files for portfolio/scan state

3. Top 5 Obstacles to Intraday

🚧 1 — Daily-bar assumption is pervasive signal_engine.py, strategies.py, and market_scanner.py are hardcoded for daily OHLCV with no interval abstraction. These must be rewritten, not modified. Touching them risks breaking the swing platform.
🚧 2 — Python spawned per request cannot handle 1-min ticks Cold-start cost is 400–800 ms per request. For intraday at 50–100 API calls/minute, this is a hard throughput ceiling. The hot path needs a long-running FastAPI or gRPC process.
🚧 3 — No VWAP, RVOL, ORB, or gap analysis exists anywhere These four indicators are absent from the entire codebase. They are prerequisites for every intraday strategy and must be built from scratch.
🚧 4 — No Kite WebSocket integration The current 30-second REST polling via kite_quote_provider.py is too stale for intraday. A 30-second-old quote can result in 0.3–0.5% adverse fills. Kite's KiteTicker WebSocket is required.
🚧 5 — Confidence calibration is trained on swing (daily) data The Isotonic regression model in confidence_calibration.py is calibrated on multi-day hold outcomes. Applying it to intraday trades will produce systematically miscalibrated win probabilities. A separate model must be trained on ≥ 200 intraday paper trades.

4. Existing Strengths to Preserve

✅ Production-grade safety architecture phase20_gates + circuit_breaker + phase22 readiness checklist provide institutional-quality safeguards. Reuse entirely.
✅ Durable scan state (PostgreSQL-backed leases) scan_state_store.py prevents duplicate scans and race conditions on Autoscale. Works identically for intraday.
✅ Audit trail discipline Every trade records frozen-at-entry indicator values via trade_intelligence.py. Deduplication by deterministic ID. Critical for intraday learning.
✅ Layered model governance phase14_governance (drift detection + human approval gate) is protocol-agnostic. Transfer to intraday unchanged.
✅ Comprehensive alert infrastructure PostgreSQL-backed alert queue with exponential backoff, idempotency keys, dead-letter handling, and Expo push delivery. Fully reusable.
✅ Data quality taxonomy live_data_provider.py classifies data as LIVE / RECENT / STALE / DEGRADED / UNAVAILABLE. Framework is correct; freshness TTLs must shrink for intraday (from 15 min → 2 min).

7. Intraday NSE Cost Model (Reference)

Cost Component Rate (MIS Intraday Equity)
Brokerage ₹20 per order (Zerodha flat)
STT (Securities Transaction Tax) 0.025% of sell-side turnover
Exchange charges (NSE) 0.00345% of total turnover
SEBI Turnover Fee 0.0001% of total turnover
GST 18% on (brokerage + exchange charges)
Stamp Duty 0.003% of buy-side turnover

Verify against current Zerodha brokerage schedule before implementing the cost engine.

8. Phased Migration Roadmap

A

Infrastructure Preparation  2–3 weeks

Add DB columns (product_type, timeframe, session_id). Create intraday_sessions + minute_ohlcv_cache tables. Implement Kite WebSocket tick ingestion. Migrate Python to long-running process. Add WebSocket server (Node.js) for real-time frontend.

B

Core Intraday Indicators  2–3 weeks

Implement vwap_engine.py (session-reset VWAP + SD bands). Implement rvol_calculator.py. Implement gap_analyser.py. Implement orb_detector.py (configurable 15/30 min). Implement session_features.py (TOD encoding).

C

Intraday Signal Engine  2–3 weeks

Implement intraday_strategies.py (ORB, VWAP reversion, Momentum burst). Implement intraday_signal_engine.py. Implement intraday_scanner.py (RVOL-filtered universe). Backtest on 3 months of 1-min historical data — must show positive expectancy before enabling automation.

D

Risk & Execution  2 weeks

Implement cost_engine.py (full NSE MIS model). Implement intraday_sizer.py (MIS leverage + slippage). Implement intraday_risk_engine.py (session cap + position limit). Extend paper_trader.py with MIS mode. Add mandatory 15:15 square-off hook to phase20_scheduler.py.

E

AI & Learning  3–4 weeks

Collect ≥ 200 intraday paper trades with full feature capture. Retrain confidence_calibration.py on intraday outcomes. Extend adaptive_learning.py with VWAP/ORB/TOD feature dimensions. Re-run walk-forward with session-day windows. Validate: win rate > 45%, profit factor > 1.3.

F

Frontend & Monitoring  2 weeks

Build IntradayDashboard.tsx (session P&L, live VWAP, ORB status, square-off countdown). Build SessionReplay.tsx (1-min chart). Add TOD performance heatmap and strategy-by-session-type analytics.

G

Production Readiness  2 weeks

Run adapted phase22_readiness checklist. Add API auth middleware. Migrate remaining JSON state to PostgreSQL. Security review (no real orders placeable). Write intraday runbook and session start/end procedures.

⏱ Total estimated timeline: 15–19 weeks Assumes a single developer. The swing trading platform remains completely untouched throughout all phases.
