Fix the Research Factory experiment submission and export pipeline.

Current problems:
1. Clicking “Queue Experiment” fails with:
   SyntaxError: Failed to execute 'json' on 'Response': Unexpected end of JSON input
2. The downloaded CSV and JSON exports are actually HTML pages instead of real data files.
3. Both the Custom Experiment form and template Preview & Queue dialog show the same submission failure.

Scope:
Fix only the Research Factory/API submission, queue persistence, status refresh, and export handling. Do not change the trading strategy logic, ranking logic, walk-forward calculations, live paper-trading behaviour, or model thresholds.

A. Diagnose the request flow
Trace the full flow from:
- Custom Experiment → Queue
- Template Preview → Queue Experiment
- Parameter Sweep → Preview & Queue
through the frontend API client, server route, validation layer, database/storage layer, and response handler.

Use the browser Network tab and server logs to identify:
- request URL and HTTP method
- submitted payload
- response status
- response Content-Type
- backend exception or routing failure
- whether the request is reaching the correct server route

B. Fix backend API responses
Every experiment endpoint must always return valid JSON, including errors.

Successful create response example:
{
  "success": true,
  "experiment": {
    "id": "...",
    "name": "...",
    "status": "QUEUED"
  }
}

Error response example:
{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Readable error message",
    "details": {}
  }
}

Requirements:
- Never return an empty body.
- Never return an HTML error page from an API route.
- Set Content-Type to application/json.
- Wrap route handlers in error handling.
- Log the full backend error and request ID server-side.
- Return the correct 4xx or 5xx status.
- Ensure all execution paths explicitly return a response.
- Verify the route is registered under the same URL used by the frontend.

C. Fix frontend response handling
Do not call response.json() blindly.

Implement a shared safe API helper that:
1. reads response.text()
2. checks response.ok
3. checks Content-Type
4. parses JSON only when a non-empty valid JSON body exists
5. reports status code, endpoint, and a shortened response body when parsing fails

Example behaviour:
- Empty body → “Server returned an empty response”
- HTML body → “Expected JSON but received HTML”
- Non-2xx response → show backend error message
- Valid success JSON → proceed normally

Prevent duplicate submissions:
- Disable the Queue button while submitting.
- Show a loading state.
- Use an idempotency key or disable repeated clicks.
- Re-enable the button after success or failure.

D. Validate and normalize experiment payloads
Use one shared schema for custom, template, and batch experiments.

Validate:
- name is required
- training period
- test period
- step size
- start and end dates
- start date is before end date
- max holding days
- minimum confidence
- intrabar rule
- universe size
- tags
- template or batch metadata

Normalize UI values consistently, for example:
- “1 year” and “1yr” must map to one canonical backend value
- “3 months” and “3mo” must map to one canonical value
- empty optional dates must become null, not invalid strings
- numeric inputs must be submitted as numbers

Return field-level validation errors to the UI.

E. Persist and verify the queue item
On successful submission:
- Create a unique experiment ID.
- Save the complete normalized configuration.
- Save status as QUEUED.
- Save created_at and updated_at.
- Preserve template name, batch ID, and tags when applicable.
- Return the saved database record.

After submission:
- Automatically close the preview modal if applicable.
- Show a success toast containing the experiment name and ID.
- Refresh the Queue tab automatically.
- The newly queued experiment must be visible immediately.
- Preserve the selected Research Factory tab.
- Poll or refresh status while experiments are QUEUED or RUNNING.
- Refresh Batches and Leaderboard after completion.

F. Fix CSV and JSON exports
The current export downloads contain the Vite/React HTML page instead of experiment data.

Investigate:
- wrong export URL
- frontend fallback route intercepting `/api/...`
- missing API prefix
- authentication redirect
- server route order
- incorrect Content-Disposition
- using window.location against a SPA route
- returning index.html when the export route is not found

CSV endpoint must return:
- Content-Type: text/csv; charset=utf-8
- Content-Disposition: attachment; filename="research-factory-experiments-<timestamp>.csv"
- actual CSV rows

JSON endpoint must return:
- Content-Type: application/json; charset=utf-8
- Content-Disposition: attachment; filename="research-factory-experiments-<timestamp>.json"
- actual JSON data

Exported content should include, where available:
- experiment ID
- name
- status
- tags
- template
- batch ID
- created and completed timestamps
- training/test/step periods
- start/end dates
- maximum holding days

- universe size
- trades

- net P&L
- profit factor
- expectancy
- Sharpe
- drawdown
- win rate
- evidence status
- score
- rejection reason

Do not allow the SPA catch-all route to handle API or export URLs.
