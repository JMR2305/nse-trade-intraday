PHASE 11 — LIVE DATA FOUNDATION, REAL-TIME REFRESH, UI POLISH, AND PAPER-TRADING SAFETY

Continue from the existing NSE Trader codebase. Do not rebuild the app from scratch and do not remove working functionality.

PRIMARY GOAL

Create a production-ready live-data foundation that makes the application update reliably during NSE trading hours while remaining strictly paper-trading and research-only.

This phase must not place, modify, or cancel any real broker order.

==================================================
1. NON-NEGOTIABLE SAFETY RULES
==================================================

1. Preserve paper-trading-only behavior.
2. Do not enable real-money execution.
3. Do not create automatic broker order placement.
4. Broker integration may read account, holdings, positions, margins, quotes, and order status only.
5. Any execution-related UI must remain disabled and clearly labelled:
   “PAPER TRADING ONLY — NO LIVE ORDERS”
6. Never fabricate live data.
7. If live data is unavailable, display the exact fallback source, age, and limitation.
8. No recommendation may become BUY or STRONG BUY when the required live-data fields are stale or unavailable.
9. Preserve all existing no-lookahead research protections.
10. Existing working routes and reports must continue functioning.

==================================================
2. LIVE DATA ARCHITECTURE

==================================================
3. REAL-TIME STREAMING
==================================================

Implement a WebSocket or server-sent-events layer between the backend and frontend.

Requirements:

- Maintain one shared backend connection to the market-data provider.
- Avoid opening a separate external provider connection for every browser tab.
- Broadcast normalized market updates to connected clients.
- Subscribe only to required symbols.
- Reconnect automatically with exponential backoff.
- Add heartbeat monitoring.
- Detect stale streams.
- Prevent duplicate subscriptions.
- Restore subscriptions after reconnect.
- Store the last valid quote per symbol.
- Log connection and reconnection events.
- Do not crash the application when the provider disconnects.

Suggested event types:

- market.quote
- market.status
- market.health
- scan.started
- scan.progress
- scan.completed
- scan.failed
- portfolio.updated
- recommendation.updated
- notification.created

==================================================
4. MARKET-HOURS-AWARE BEHAVIOUR
==================================================

Use Asia/Kolkata timezone consistently.

Implement states:

- PRE_OPEN
- OPEN
- CLOSED
- WEEKEND
- HOLIDAY
- PROVIDER_UNAVAILABLE
- DELAYED

Do not hardcode only Monday–Friday logic.

Create a configurable market calendar service so NSE holidays can be updated.

During OPEN:
- Enable streaming updates.
- Show live-data freshness.
- Refresh derived indicators at a controlled interval.
- Do not continuously rerun the complete strategy engine for every tick.

Outside market hours:
- Stop unnecessary high-frequency polling.
- Display the last market close.
- Display the timestamp of the last valid data.
- Permit manual research scans using cached or historical data.
- Clearly label such scans as non-live.

==================================================
5. SCAN ORCHESTRATION
==================================================

Separate lightweight quote updates from full scans.

Implement:

A. Lightweight refresh
- Updates quotes, P&L, market status, and data health.
- Does not generate duplicate trades.
- Does not rerun expensive historical analysis.

B. Full strategy scan
- User-triggered or scheduled at a configurable interval.
- Runs with a distributed or database lock.
- Prevents two scans from running simultaneously.
- Generates a unique scan ID.
- Saves start time, end time, status, source, data freshness, and errors.
- Emits progress updates to the frontend.

C. Post-scan processing
- Update recommendations.
- Update portfolio plan.
- Create notifications.
- Save a diagnostic snapshot.
- Never execute a broker order.

Add idempotency so refreshing the page or retrying a request does not create duplicate scan results or paper trades.

==================================================
7. DATA FRESHNESS GATES
==================================================

Create centralized freshness rules.

Example configurable defaults:

- Live quote healthy: age <= 15 seconds during market hours
- Delayed: age > 15 seconds and <= 60 seconds
- Stale: age > 60 seconds
- Historical or fallback: never treated as live

Recommendations must obey:

- STRONG BUY and BUY require healthy live price and volume.
- WATCH may be shown with delayed data but must display a warning.
- Stale or fallback data must result in NO TRADE, WATCH, or DATA UNAVAILABLE according to current safety logic.
- Existing holdings may still receive EXIT warnings if risk rules can be evaluated safely, but the reason must identify missing or stale data.
- Never show fake confidence precision when evidence is missing.

Add a “Data Qualification” section to every expanded trade explanation showing:

- Required fields
- Available fields
- Missing fields
- Freshness
- Source
- Gate outcome

9. PERFORMANCE ANALYTICS VALIDATION
==================================================

The existing Performance Analytics page currently has very few closed trades.

Ensure:

- All estimated metrics are clearly labelled.
- Sharpe, Sortino, Calmar, volatility, beta, and learning scores require minimum sample thresholds.
- Ratios derived from fewer than the configured minimum observations show:
  “Estimated — limited evidence”
  or
  “N/A — insufficient history”
- Do not present extreme values as reliable.
- Add the exact sample count beside every estimated metric.
- Benchmark periods must match the portfolio evaluation period.
- Do not compare a short portfolio period against an unrelated benchmark period.
- Validate that total return amount, total return percentage, equity curve, monthly return, and trade-level P&L reconcile.

Add automated reconciliation checks and display a warning if totals differ beyond a small tolerance.
