SPECIFIC ITEMS TO VERIFY

A. Robots handling
The current RobotsChecker may fail open when robots.txt retrieval or parsing fails.

Required:
- Review this behavior.
- For production-approved sources, ambiguous robots status must fail closed.
- A source-specific explicit compliance override may be allowed only through reviewed configuration.
- Add tests for:
  - robots allow
  - robots disallow
  - robots fetch failure
  - robots parse failure
  - cached robots result
  - explicit reviewed override

B. SSRF and redirects
Verify:
- every redirect target is validated
- localhost is blocked
- private RFC1918 ranges are blocked
- link-local addresses are blocked
- metadata-service IPs are blocked
- DNS resolution is checked
- redirect loops and excessive redirects are rejected
- URL overrides cannot escape the approved source host/path policy

C. Streaming and resource controls
Verify:
- responses are streamed
- download stops when size limit is exceeded
- compressed/decompressed size risks are handled
- unsupported content types are rejected
- timeouts and retry limits are bounded
- 4xx errors are not retried except approved cases
- concurrency limits work
- hourly rate limits work

D. Source registry persistence
Verify that:
- approved sources are stored persistently
- enable/disable survives process restart
- CLI and API use the same repository
- emergency source disable is reliable

E. Parser correctness
Verify:
- Scrapling is actually used when required
- production does not silently fall back to an inferior parser
- missing selectors produce PARSER_MISMATCH
- per-record publication dates are extracted correctly
- one record cannot inherit another record’s date
- empty extraction never reports success

F. Deduplication
Verify:
- keys are scoped by source
- exact duplicates are ignored
- changed content updates the existing logical record
- records_updated increments correctly
- duplicates_ignored is not used for changed content
- new snapshots are preserved for changed content

G. API correctness
Verify:
- all declared filters match real database fields
- pagination is bounded
- totals use SQL COUNT rather than loading all rows
- raw content is never exposed
- internal filesystem paths are not leaked
- readiness checks database, storage, and required parser availability

H. Database and migrations
Verify:
- Alembic is the source of truth
- startup does not silently create or mutate schema with create_all
- fresh database migration works
- upgrade path works
- SQLite test mode and PostgreSQL mode are both handled correctly

I. Docker
Verify:
- package install order is correct
- runtime image does not unnecessarily include dev dependencies
- non-root user is used where practical
- healthcheck works
- environment variables are documented
- container starts successfully

J. Test isolation
Verify:
- no test contacts the internet
- local fixtures are used
- network access is blocked or mocked
- failure in one source does not affect another
- cancellation and partial failures are covered
