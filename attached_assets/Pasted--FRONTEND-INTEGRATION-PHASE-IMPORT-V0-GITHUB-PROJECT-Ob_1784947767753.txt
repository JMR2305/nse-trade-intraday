## Phase 1 — Import

1. Import the V0 GitHub repository into the current Replit workspace.

2. Preserve Git history if possible.

3. Do not overwrite the existing backend.

4. Keep frontend and backend isolated until integration is verified.

--------------------------------------------------

## Phase 2 — Build Verification

Verify:

- Dependencies install successfully
- Frontend builds successfully
- No missing packages
- No broken imports
- No incompatible framework versions

Fix only build and compatibility issues.

Do not redesign the application.

--------------------------------------------------

## Phase 3 — Architecture Review

Review the imported frontend.

Identify:

- Framework
- Routing
- Component hierarchy
- State management
- Styling system
- API layer
- Authentication flow
- Mock services
- Static data
- Dashboard structure

Prepare an architecture summary.

--------------------------------------------------

## Phase 4 — Integration Mapping

Map every frontend page to the existing backend.

For each page identify:

- Backend API required
- Existing implementation
- Missing endpoint
- Mock data currently used
- Integration complexity
- Dependencies

Do NOT replace mocks yet.

--------------------------------------------------

## Phase 5 — Compatibility Review

Verify compatibility with:

- Portfolio Service
- Strategy Engine
- Risk Engine
- Execution Engine
- Market Data
- Broker Layer
- AI Forecast

Ensure the frontend consumes backend services without bypassing architecture.

The frontend must never:

- Place orders directly
- Perform risk validation
- Maintain portfolio state
- Connect to broker APIs

All business logic must remain in the backend.
