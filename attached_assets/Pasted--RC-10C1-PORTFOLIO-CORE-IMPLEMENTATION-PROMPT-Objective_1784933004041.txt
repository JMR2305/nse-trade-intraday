# RC-10C1 — PORTFOLIO CORE IMPLEMENTATION PROMPT

## Objective

Implement RC-10C1: Portfolio Core for the NSE Intraday Trading Platform.

This phase must introduce production-grade portfolio state, capital allocation, position sizing, exposure control, P&L accounting, persistence, and reconciliation.

Do not implement UI dashboards or advanced analytics in this batch.

Do not enable live trading.

Maintain full backward compatibility with:

- RC-6 Market Data
- RC-7 Execution Engine
- RC-8 Risk Engine
- RC-9 Strategy Engine
- RC-10A Market Intelligence
- RC-10B AI Forecast
- RC-10D Broker Layer

Frozen invariants:

- RC-8 remains the final risk authority.
- RC-7 remains the execution authority.
- RC-10D remains the only broker integration layer.
- No portfolio component may call Zerodha directly.
- No portfolio component may place, modify, or cancel orders directly.
- RC-10B remains advisory-only.
- Paper trading remains the default.
- Live trading remains structurally disabled.

Required flow:

Strategy
→ SignalRouter
→ Portfolio Pre-Check
→ RC-8 Risk Engine
→ RC-7 Execution Engine
→ RC-10D Broker Layer

Feedback flow:

RC-10D Broker State
→ Portfolio Reconciliation
→ Portfolio State
→ Exposure / P&L / Buying Power
→ Strategy and Risk Context

21. REQUIRED END-TO-END TESTS
------------------------------------------------------------

At minimum:

1. Approved paper trade

Strategy signal
→ portfolio allocation
→ position sizing
→ RC-8 approval
→ RC-7 execution
→ RC-10D paper broker
→ fill
→ portfolio position update
→ P&L update
→ persistence

2. Insufficient buying power

Signal
→ portfolio rejection
→ RC-8 and broker not called

3. Exposure breach

Proposed order exceeds instrument or sector limit
→ rejection
→ audit event
→ broker not called

4. Partial fill

Order partially filled
→ position updated correctly
→ reserved capital adjusted
→ remaining pending exposure retained

5. Duplicate fill

Same fill received twice
→ applied once

6. Broker mismatch

Broker position differs from local
→ reconciliation discrepancy persisted
→ portfolio readiness degraded
→ new orders blocked

7. Restart recovery

Snapshot and events restored
→ broker state reconciled
→ no duplicate position or P&L event
→ readiness restored

8. Daily loss breach

Daily loss exceeds configured limit
→ new allocations blocked
→ existing cancellation and reconciliation remain available

------------------------------------------------------------

RC-10C1 is ready for audit only when:

✓ One authoritative portfolio state exists

✓ Portfolio events are idempotent and replayable

✓ Position lifecycle supports partial fills and recovery

✓ Capital reserve is protected

✓ Position sizing uses Decimal arithmetic

✓ Pending orders are included in exposure

✓ Portfolio limits are enforced

✓ P&L is deterministic and auditable

✓ Broker-state reconciliation is implemented

✓ No direct Zerodha dependency exists

✓ RC-8 remains the final risk authority

✓ RC-7 remains the execution authority

✓ Stale or unreconciled portfolio state blocks new orders

✓ Snapshot and replay recovery are verified

✓ All new tests pass

✓ All RC-6 through RC-10D regression tests pass

✓ Independent audit reports zero Critical findings

✓ All High findings are resolved before freeze
