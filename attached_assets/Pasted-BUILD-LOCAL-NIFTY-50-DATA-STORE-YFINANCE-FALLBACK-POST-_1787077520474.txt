BACKGROUND:
The attached scan-count/data-fetch report proves:
- 2026-08-18 had only 18 completed scans, 19 started.
- The 75 figure is scheduler ticks, not completed scans.
- Completed scan count is low because scans often take 7–22 minutes.
- The bottleneck is yfinance bulk fetch, not Kite.
- Kite LTP overlay takes <1 second.
- yfinance is currently used for 6-month daily OHLCV and indicators.
- Kite is used for live current_price and execution_price.

GOAL:
Stop fetching full yfinance 6-month daily history every scan.
Create a persistent local NIFTY 50 data store so scans use local OHLCV/company data first, and yfinance only as fallback or scheduled refresh source.

The final design should be:
- Local data first.
- yfinance fallback.
- Kite LTP for live price and execution.
- Post-market refresh/appending of latest daily candle.
- Faster scans.
- Higher completed scan count.
- No change to live-order safety.

TASK 4 — CHANGE LIVE SCAN FETCH POLICY

Implement this policy:

A. Before market open / first scan:
- Check local daily_ohlcv_cache for each symbol.
- Ensure at least 6 months of daily bars are available.
- Ensure latest expected trading date is present or acceptable.
- If missing, fetch only missing ranges from yfinance.
- Do not refetch full 6-month history if cache is already complete.

B. During market hours:
- Do NOT call yfinance bulk download every 5 minutes.
- Use local daily_ohlcv_cache for indicators.
- Apply Kite LTP overlay for current_price and execution_price.
- If cache is fresh enough, scan should run from local data.
- Only call yfinance during market hours for symbols with missing/stale cache.

C. Post-market close:
- After 15:30 IST, run a postmarket daily-bar refresh job.
- Fetch today’s/yesterday’s final daily candle from yfinance for all NIFTY 50 symbols.
- Append/update only the latest trading date in local cache.
- Record refresh status.
- Do not disturb closed trade/eod logic.
- This job should prepare tomorrow’s indicators before market opens.

D. Nightly / off-market:
- Verify cache completeness for the next session.
- Validate all symbols have required 6-month lookback.
- Rebuild corrupted/missing ranges if needed.
- Generate data readiness report.

E. Fallback:
- If local cache is available and recent, use it even if yfinance fails.
- If local cache is stale beyond allowed threshold, mark symbol STALE and block BUY.
- If no cache exists, mark symbol UNAVAILABLE.
- yfinance should become fallback, not primary per-scan dependency.

TASK 6 — POST-MARKET APPEND JOB

Add a scheduled/triggered post-market job:

post_market_daily_data_refresh()

Run after market close, suggested 16:05 IST or on first post-close scheduler tick.

It should:
1. Load NIFTY 50 local company master.
2. Fetch latest daily OHLCV candle from yfinance.
3. Append/update today's trading date for every available symbol.
4. Preserve previous rows.
5. Detect split/corporate-action anomalies.
6. Mark missing symbols.
7. Mark LTIM separately as known provider issue if still missing.
8. Emit DATA_CACHE_POSTMARKET_REFRESH_COMPLETED.
9. Generate refresh summary for dashboard.

If yfinance is unavailable post-market:
- Keep previous cache.
- Emit DATA_CACHE_POSTMARKET_REFRESH_FAILED.
- Do not break next scan if cache is still within safe age.
