ADD QUALITY-BASED ALLOCATION OVERRIDE — 2x / 3x POSITION SIZING

Use these controlling reports:

- APEXQUANT_OHLCV_CACHE_MIGRATION_SUMMARY.md
- APEXQUANT_REMOVE_LTIM_AND_CAPITAL_100000_MIGRATION_REPORT.md, if already generated

Do not enable live orders.
Do not call broker order APIs.
PAPER ONLY.
Do not reduce existing safety gates.
Do not blindly increase allocation only because confidence is high.

GOAL:
Add a controlled allocation override rule:
If a stock has an exceptionally good score and lower measured risk, the system may increase allocation by 2x or 3x.

This should be implemented as:
QUALITY_ALLOCATION_OVERRIDE

The override must increase allocation only when:
- signal quality is very strong
- risk is low
- R:R is strong
- price source is reliable
- data is fresh
- circuit breaker is clear
- sector/portfolio/cash limits still allow it

base_order_notional =
- for BOOTSTRAP_AUTO: bootstrap cap, currently ₹15,000

TASK 2 — ADD OVERRIDE TIERS

Add three sizing tiers:

TIER 0 — NORMAL
- allocation_multiplier = 1.0
- use existing sizing rules

TIER 1 — HIGH_QUALITY_2X
- allocation_multiplier = 2.0
- candidate can request up to 2x base_order_notional

TIER 2 — EXCEPTIONAL_QUALITY_3X
- allocation_multiplier = 3.0
- candidate can request up to 3x base_order_notional

But final notional must be:

final_notional = min(
    base_order_notional * allocation_multiplier,
    available_cash,
    portfolio_remaining_cap,
    sector_remaining_cap_or_override_cap,
    risk_based_max_notional,
    absolute_override_cap
)

TASK 3 — 2X OVERRIDE CRITERIA

Allow 2x only if ALL conditions pass:

- confidence >= 85
- opportunity_score >= 80
- trade_quality_score >= 80
- R:R >= 2.5
- quote_reliable = true
- current_price_source = kite_live_ltp
- execution_price_source = kite_live_ltp
- ohlcv_source = local_yfinance_cache
- data_quality = LIVE or NEAR_LIVE
- cache_hit = true
- circuit_breaker_tripped = false
- no loss today
- no existing OPEN position in same symbol
- max daily trades not exceeded
- sector cap after trade does not exceed configured limit unless sector override explicitly allows it
- rupee risk at stop-loss remains within allowed risk budget

TASK 4 — 3X OVERRIDE CRITERIA

Allow 3x only if ALL stricter conditions pass:

- confidence >= 90
- opportunity_score >= 85
- trade_quality_score >= 88
- R:R >= 3.0
- stop_distance_pct is low
- ATR/volatility risk is low or normal, not HIGH_VOL
- signal remains valid for 2 consecutive scans
- quote_reliable = true
- Kite LTP verified
- local OHLCV cache fresh
- circuit breaker clear
- no loss today
- no MARKET_CLOSE_EXIT_BLOCKED events today
- no stale data warning for that symbol
- no duplicate position
- rupee risk at stop-loss remains within allowed risk budget
- final notional must not breach total portfolio deployed cap
- final position must be explainable in audit logs

TASK 5 — RISK-BASED MAX NOTIONAL

Do not size only from available cash.

Calculate stop-loss rupee risk:

risk_per_share = abs(entry_price - stop_loss)
position_risk = risk_per_share * qty

Default rule:
- normal trade risk <= 1% of capital
- 2x override risk <= 1.5% of capital
- 3x override risk <= 2.0% of capital

For ₹100,000:
- normal max rupee risk = ₹1,000
- 2x max rupee risk = ₹1,500
- 3x max rupee risk = ₹2,000

If the stop-loss is wider, reduce quantity.
If the stock is lower-risk with tight stop, allow larger quantity.

This ensures “lesser risk” actually means position risk is still controlled.

TASK 6 — SECTOR AND PORTFOLIO SAFETY

Do not allow one trade to consume the full account.

Hard caps:
- portfolio_deployed_cap_pct remains 80%
- daily_loss_limit remains 3%
- circuit breaker remains unchanged
- max_concurrent_positions remains unchanged

Sector handling:
Option A, safer default:
- Do not override sector cap.
- 2x/3x can increase per-stock sizing only until sector cap is reached.

Option B, if implemented:
- Add separate `sector_override_enabled` setting.
- Default false.
- If true, allow sector cap to increase only for 3x tier, capped at 50% of capital.
- Must emit `SECTOR_CAP_OVERRIDE_USED`.

Use Option A unless operator explicitly approves Option B.
