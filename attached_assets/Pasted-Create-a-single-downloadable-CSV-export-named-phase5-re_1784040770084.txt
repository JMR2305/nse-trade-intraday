CSV RULES

1. Use UTF-8 encoding.
2. Properly escape commas, quotation marks, and multiline text.
3. Do not put arrays or objects into cells without serializing them as compact JSON.
4. Use one consistent header row.
5. Leave unavailable values blank; do not invent values.
6. Clearly mark insufficient evidence and low sample sizes.
7. Include research-only and analysis-only labels where applicable.
8. Include failed, rejected, incomplete, and empty-result records rather than hiding them.
9. Do not export secrets, API keys, passwords, tokens, cookies, personal information, or broker credentials.
10. Do not expose internal stack traces. Use a safe error summary in the notes column.
11. Ensure numeric fields contain raw numeric values without currency symbols or percentage signs. Use separate unit-aware column names such as net_return_pct.
12. Add source_page_url and source_record_id so every row can be traced back to the UI or database record.

USER INTERFACE

Add a button in Research Factory labelled:

Export Phase 5 Review CSV

Place it near the existing CSV/JSON export controls.

When clicked:
- Generate the file from current stored data.
- Download phase5_review_export.csv.
- Show a success message containing the number of rows exported.
- Show a clear error message if generation fails.
- Do not call response.json() blindly. Verify the HTTP status and Content-Type first.
- For a file response, handle it as a Blob.
- If the server returns an error, safely read text or JSON depending on Content-Type.

VALIDATION

After implementation:

1. Generate the CSV.
2. Confirm it opens correctly in Excel or Google Sheets.
3. Confirm the column count is identical for every row.
4. Confirm there are no malformed rows.
5. Confirm multiline explanations remain inside one cell.
6. Confirm no secrets are present.
7. Confirm every listed Phase 5 page has at least one implementation-audit row, even when that feature is missing.
8. Report:
