2. CONFIDENCE GATE API
=========================================================

Implement the planned public interface:

async should_route(
    signal,
    context,
    min_confidence,
    prefetched_forecast=None
) -> tuple[bool, Optional[ForecastResult]]

Required behaviour:

- no configured threshold:
  return (True, None) without filtering

- forecast unavailable or adapter error:
  return (True, None)

- confidence below threshold:
  return (False, forecast)

- confidence equal to or above threshold:
  return (True, forecast)

The threshold must come from:

StrategyConfig.parameters["min_forecast_confidence"]

Do not use an active constructor default that silently filters strategies.

Remove or disable default behaviour that blocks:

- confidence below 0.55
- NEUTRAL direction

unless the strategy explicitly requests such behaviour in its parameters.

Fail-open is mandatory.

The existing synchronous apply() method may remain only as a private or compatibility utility if useful.

3. RUNTIME FORECAST WIRING
=========================================================

Wire the AI forecast pipeline into the actual runtime path.

The intended flow is:

StrategyRuntime._process_bar(bar)
  → build StrategyContext
  → obtain MultiTimeframeContext for the signal instrument
  → optionally start Kronos prefetch
  → strategy.on_bar(...)
  → when a Signal exists:
       read min_forecast_confidence from StrategyConfig.parameters
       invoke ForecastConfidenceGate.should_route()
       suppress only when explicitly configured and below threshold
       enrich routed signal metadata when forecast succeeds
       pass the enriched signal through the existing routing path

Do not bypass or reorder:

- conflict resolution
- RC-8 Risk
- RC-7 Execution
- existing SignalRouter safety checks

The forecast layer must run before the final routing callback, but it must not directly place or submit orders.

8. BENCHMARK CALCULATIONS
=========================================================

BenchmarkReport must include:

- directional_accuracy
- calibration_error
- sample_count

Directional accuracy:

correct directional predictions / completed predictions

Calibration error:

mean absolute error between predicted confidence and binary correctness:

abs(confidence - outcome)

where outcome is:

- 1 for correct
- 0 for incorrect

Requirements:

- completed outcomes only
- last_n ordered by computed_at descending
- optional instrument filter
- no records:
  return zero-valued report, do not raise
- DB failure:
  return zero-valued report and log warning

record_outcome() must derive actual direction consistently from actual_return:

- actual_return > 0 → UP
- actual_return < 0 → DOWN
- actual_return == 0 → NEUTRAL
