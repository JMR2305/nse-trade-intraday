TASK #945 — MISSION CONTROL KITE FALLBACK ALERT + DURABLE INCIDENT HISTORY

GOAL:

Add an in-app Mission Control alert whenever execution-grade current-price
authority falls away from ZERODHA_KITE, and persist every fallback episode for
future audit/reference.

NO EXTERNAL NOTIFICATIONS.

Do NOT add:
- Telegram
- email
- SMS
- Slack
- mobile push
- webhook notification providers

SCOPE:

1. Mission Control live alert banner
2. Durable fallback incident history
3. Recovery tracking
4. Deduplication / incident lifecycle
5. Read-only incident history UI
6. Fail-closed execution/readiness semantics preserved

IMPORTANT SAFETY:

Do NOT:
- change trading strategy
- enable automatic entries
- enable bootstrap
- enable controlled execution
- enable live broker orders
- change active universe
- change portfolio/capital
- change provider fallback policy
- treat Yahoo/NSE as execution-grade equivalent to Kite
- trigger scans manually for testing in production

==================================================
1. DEFINE FALLBACK EVENT
==================================================

For CURRENT PRICE / execution-grade quote authority:

NORMAL:
current_quote_provider = ZERODHA_KITE

FALLBACK / DEGRADED:
current_quote_provider != ZERODHA_KITE

Examples:
YFINANCE
NSE
CACHE
STALE
UNAVAILABLE
SYNTHETIC
UNKNOWN

Historical OHLCV provider is separate.

YFINANCE as historical_ohlcv_provider must NOT trigger this alert.

==================================================
2. INCIDENT SEVERITY
==================================================

Use:

WARNING
- 1 or a small subset of symbols affected
- current data still partially available

HIGH
- fallback affects multiple symbols
- persists beyond one normal scan cycle
- readiness degraded

CRITICAL
- most/all active symbols affected
- provider unavailable
- stale/synthetic/unavailable execution-grade data
- trading_data_ready becomes false

Severity rules must be deterministic and configurable.

==================================================
4. INCIDENT DEDUPLICATION
==================================================

Do not create a new row every scan.

For the same continuous fallback episode:

update:
last_detected_at
latest_scan_id
affected_symbols
actual_provider
quote age
severity
detection_count

Keep the same incident ID.

Create a new incident only after:

previous incident = RECOVERED

and a new fallback begins.

==================================================
5. RECOVERY RULE
==================================================

Recovery requires authoritative current-price health to return to:

current_quote_provider = ZERODHA_KITE

and required current quote coverage/freshness is healthy.

On recovery:

status = RECOVERED
recovered_at = timestamp

Record total duration.

Do not delete the incident.
