1. FIX PRODUCTION ZERODHA SESSION ACCESS

Investigate why the browser-facing Kite Connect page can be authenticated, but the unattended production scheduler reports:

- Kite Connect not configured
- Zerodha login required
- no active session

Verify:

- production ZERODHA_API_KEY is present
- production ZERODHA_API_SECRET is present

- the scheduler reads the same token/session record
- token timestamp and expiry are stored correctly
- development and production secrets are not different
- Autoscale instances do not rely on process memory

Use the production database or durable shared secret/session storage as the authoritative source.

Do not store the access token in browser local storage, local JSON files, or process memory only.
