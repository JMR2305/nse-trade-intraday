1. Executive Summary

1.1 What is ApexQuant AI?

ApexQuant AI is a paper-only NSE trading research platform built on a multi-agent AI architecture. Its core purpose is to:

  • Scan NIFTY 50 (51 symbols after TATAMOTORS demerger) every 4–5 minutes during market hours
  • Run each symbol through a multi-layer AI pipeline: data quality → signal → strategy → risk → decision → execution
  • Generate BUY / WATCH / IGNORE recommendations with confidence scores, opportunity scores, and position-sizing guidance
  • Execute paper (simulated) trades when all gates pass, building a tracked portfolio
  • Learn from the outcomes of those paper trades to improve future decisions

No live orders have ever been placed. Zerodha broker APIs are never called for order submission. Live execution is structurally disabled.

27. BTT/Replay Event Namespace Guardrail (v4.3)

pipeline_events._emit_unsafe() blocks any ORDER_SUBMITTED / ORDER_EXECUTED / ORDER_REJECTED / ORDER_CANCELLED event in LIVE mode whose payload.trade_id is present but does NOT start with P20-. Warning is logged and event is discarded without DB write. Backtest events use emit_replay() which stamps mode="BACKTEST", source="replay", canonical_trade=False.

Five consumer files also enforce the P20- filter: buy_audit.py, validation_engines.py, phase26_consistency.py, phase26_live_monitor.py, and the order lifecycle reconciler.

28. Bootstrap Mode — Activation & Operations [NEW v5.0]

28.1 What is Bootstrap Mode?

Bootstrap Mode is a mechanism to place the first paper trade automatically when the production ledger has no trading history. Without any closed trades, the AI's confidence calibration cannot self-optimise and the 6-month backtest window cannot fill with real signal outcomes. Bootstrap seeds the ledger with initial evidence so normal automated trading can take over.

Bootstrap is advisory scaffolding — it uses lower confidence thresholds and smaller position sizes specifically to generate initial data. It auto-disables after a configurable number of closed trades.

29.6 When Full OAuth is Needed

Full TOTP-based OAuth login is only needed when:

  • The Kite LTP overlay fails (API key revoked, subscription lapsed, or network issue)
  • A future feature requires Kite portfolio read access or streaming WebSocket data
  • The Bootstrap card shows the "Armed" state (amber) with the Authenticate button

To authenticate when needed:

  1. Open https://nse-trade-intraday.replit.app/trading-dashboard/ai-paper-trader (production URL only — dev URL uses wrong/old API key)
  2. Scroll to Bootstrap Mode card
  3. Tap "Authenticate Kite (Zerodha)" button
  4. Complete Kite login + TOTP on the Zerodha login page
  5. After callback redirect, kite_session_verified becomes true
Always authenticate from the production URL (nse-trade-intraday.replit.app), not the dev URL (*.replit.dev). The Zerodha callback is hardcoded to the production domain. Authenticating from the dev URL will fail with an invalid redirect error.
